# AFFCOMP 2.0 EXPERIMENTAL — NOT CONNECTED TO PRIOR SYSTEMS

**Repository:** `affcomp-labs/affcomp-factory-2-sandbox`  
**Purpose:** disposable, public, secret-free proof of a zero-click ordinary issue-to-merge loop.  
**Record:** owner decisions and state for the 2.0 program live in `affcomp-labs/affcomp-2` `docs/` (`DECISIONS.md`, `STATE.md`). This file is the sandbox's operating contract.

## Authority and boundary

GitHub issue, branch, pull-request, check, ruleset, and merge state are durable truth. This repository, its custom App, Claude subscription OAuth token, credentials, Actions logs, and any local workspace are 2.0-only. No task may read, write, authenticate to, mount, import from, or administer a prior AffComp system. Any wrong-repository or prior-system attempt stops the lane.

Only owner-authored issues carrying `af2:ready` plus exactly one of `af2:r0` or `af2:r1` enter ordinary automation. Initial work contains no production/customer data, secrets, deployments, domains, billing logic, or destructive operations. Public repository files, issues, PRs, diffs, comments, check results, workflow definitions, run metadata, and Actions logs are public; the Claude step-summary report and full output remain disabled.

## Risk and authority

- **R0:** disposable experiments, docs, tests, fixtures, and demo code. Autonomous edit, test, commit, push, PR, bounded repair, and squash auto-merge after required checks.
- **R1:** ordinary source work with the same authority, provided it does not touch factory controls, dependencies/bootstrap, permissions, migrations, releases, deployments, secrets, or sensitive data.
- **R2:** `.github/**`, `FACTORY.md`, `docs/OPERATING.md`, dependency/bootstrap files, security controls, permissions, model routing, release/deployment logic, migrations, new operating surfaces, or unusually broad changes. Work is interactive with the owner present; Codex GitHub code review is the independent reviewer, Claude review is optional, and the owner merges.
- **R3:** credentials, billing, organizations/accounts, domains, production/customer data, destructive actions, legal commitments, or break-glass activity. Owner-only unless one exact action is delegated in the current turn.

The R2 self-modification boundary is physical and operational: the worker App has no Workflows permission, `path-guard` is required, and human-authored PRs never use auto-merge. CODEOWNERS documents ownership but is not a required-review rule.

## Execution contract

Each ordinary run uses an ephemeral GitHub-hosted runner and a short-lived installation token from `affcomp-factory-2-bot`, installed only on this repository. Set `AF2_BOT_LOGIN` to `affcomp-factory-2-bot[bot]`. The App has Contents, Issues, and Pull requests read/write; it has no Workflows, Administration, Environments, Secrets, Variables, or Deployments permission.

Model access is the owner's Claude Max subscription through a Claude Code OAuth token (`claude setup-token`), stored as the repository secret `AF2_CLAUDE_CODE_OAUTH_TOKEN` and passed to the Claude Code Action as `claude_code_oauth_token`. There is no Anthropic API workspace or key. The token is tied to the owner's subscription, expires about a year after issue, and is regenerated by the owner.

The start job resolves the live repository ID, default branch, exact base SHA, and target `af2/issue-<number>` branch; it creates that branch with `git switch -c`, exports it as `CLAUDE_BRANCH`, and then invokes the full-SHA-pinned Claude Code Action. R0/R1 may change only `src/**`, `tests/**`, ordinary `docs/**` other than `docs/OPERATING.md`, and `README.md`. Deterministic guards re-read the remote branch. A rejected initial branch is deleted, `af2:ready` is removed, and the issue is marked and commented `af2:blocked` before any PR exists.

Every implementation prompt includes factory version, full repository and ID, base branch and exact SHA, target branch, issue, risk, exact model and rationale, mutation authority, objective, scope, tests, budgets, stop conditions, and required evidence.

## Checks, merge, concurrency, and budgets

Both `test` and `path-guard` are required checks. `path-guard` permits only `README.md`, `src/**`, `tests/**`, and `docs/**` other than `docs/OPERATING.md` on PRs authored by `AF2_BOT_LOGIN`; the start guard and the repair recheck apply the same allowlist, and the Claude permission profile additionally denies `docs/OPERATING.md` at tool level. A PR carrying `af2:blocked` is never scheduled for repair. Human-authored PRs pass the path check into the R2 owner-controlled lane. Squash is the only merge method. The factory and owner-dispatched revert workflow may enable native auto-merge for bot-authored PRs; human-authored PRs are never auto-merged. “Require branches to be up to date” and merge queue are off.

Start jobs use concurrency group `af2-start`; repair jobs use `af2-repair-<PR number>`; repair scheduling is ungrouped. GitHub retains only the newest pending job in a concurrency group, so the owner waits until one start begins before applying `af2:ready` to the next issue.

Limits: one initial attempt at 45 minutes, 12 turns, and a US$10 estimated-cost cap; at most two repairs at 30 minutes, 8 turns, and US$5 each. Because model access is a subscription, there is no monthly dollar cap: turn caps, attempt caps, and workflow timeouts are the spend backstops, and usage counts against the subscription's rate limits, which the owner watches. Stop on wrong identity, base mismatch, forbidden path, prior-system access, secret visibility, unexpected permission, budget exhaustion, ambiguous mutation, third failed attempt, or R2/R3 scope. Never force-push, bypass a ruleset, use admin merge, or retry an ambiguous write before durable readback.

## Operating surfaces and local fallback

`docs/OPERATING.md` is the owner operating card. Any new surface, bot, or tool requires an R2 PR that edits that file. Routine R0/R1 work stays in GitHub Actions.

Interactive R2 work runs in owner-attended local Claude Code on the owner's Windows machine, in a clone of this repository only; it is never autonomous. Before pushing, `gh auth status` and `git remote -v` must show only 2.0 identities and this repository.

## Kill, revert, and exit

Kill in order: disable `af2-factory.yml`; suspend the App installation; revoke the OAuth token (overwrite the `AF2_CLAUDE_CODE_OAUTH_TOKEN` secret with a dead value, then regenerate or invalidate the token locally); archive the disposable repository. Revert a bad autonomous squash merge by owner-dispatching `af2-revert.yml` with its full merge SHA; the workflow creates `af2/revert-<short-sha>`, opens a bot-authored PR, and enables squash auto-merge behind `test` and `path-guard`.

Exit condition for this sandbox (D-004 in the 2.0 record): one clean autonomous merge, one revert, and one observed self-repair — or three to five clean merges. The ten-issue corpus, the interactive benchmark, and the promotion metric are retired; AffComp 2.0 (`affcomp-labs/affcomp-2`) is the proving ground, and this repository is torn down rather than rescued.
